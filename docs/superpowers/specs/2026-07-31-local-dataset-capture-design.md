# EdgeDeploy 本地连续数据集采集设计

日期：2026-07-31  
状态：已由用户确认

## 目标

为现有 ESP32-S3 OV5640 固件增加一个电脑端采集控制台。用户在 Mac
浏览器中输入数据集名称和拍照间隔，通过按钮开始或停止连续拍照。每张成功
获取的原生 128×128 JPEG 立即保存到当前仓库的 `data/<数据集名称>/`
目录。

本功能保留现有 ESP32 `/capture`、`/stream` 和 `/api/status` 接口，
不要求固件直接访问电脑文件系统，也不在 ESP32 上保存图片。

## 已确认的使用方式

在仓库根目录启动 Python 程序：

```bash
python3 dataset_capture_server.py
```

然后打开：

```text
http://127.0.0.1:8000
```

控制台包含：

- ESP32 原生 128×128 MJPEG 预览；
- 数据集名称输入框；
- 拍照间隔输入框，默认 500 ms；
- “开始连续拍照”按钮；
- “停止并保存”按钮；
- 当前运行状态、成功数量、失败数量和最新文件名。

启动连续拍照时，网页先断开 MJPEG 预览，电脑端等待流连接释放，再开始请求
单帧接口。停止采集后，网页恢复 MJPEG 预览。

## 系统边界

### ESP32 固件

ESP32 继续提供：

- `GET http://192.168.4.1/capture`：返回一张原生 128×128 JPEG；
- `GET http://192.168.4.1:81/stream`：返回 MJPEG 预览；
- `GET http://192.168.4.1/api/status`：返回摄像头和流状态。

本次设计不增加 ESP32 存储、上传接口、文件系统或新的 FreeRTOS 采集任务。

### Python 本地服务

新增 `dataset_capture_server.py`，仅使用 Python 标准库，并默认只监听
`127.0.0.1:8000`。它负责：

- 提供本地控制网页和 JSON 控制接口；
- 管理唯一的后台采集线程；
- 顺序请求 ESP32 `/capture`；
- 校验 HTTP 状态、Content-Type、JPEG 头尾以及响应中的帧尺寸；
- 原子保存图片；
- 记录采集状态和元数据。

浏览器不直接写 Mac 文件系统，ESP32 也不接收或推断电脑路径。

## 数据流

### 开始采集

1. 用户输入数据集名称和拍照间隔。
2. 网页校验输入并移除 MJPEG `<img>` 的 `src`。
3. 网页调用本地服务的开始接口。
4. 本地服务检查当前没有其他采集任务。
5. 本地服务轮询 ESP32 状态，等待
   `stream_client_connected=false`，最长等待 3 秒。
6. 后台线程顺序请求 `/capture`。
7. 每张成功响应经过校验后立即落盘并追加元数据。
8. 网页定期读取本地状态并更新数量和最新文件名。

### 停止采集

1. 用户点击“停止并保存”。
2. 本地服务设置停止标志。
3. 后台线程完成当前正在处理的单张图片后退出。
4. 本地服务返回最终成功数和失败数。
5. 网页重新连接 MJPEG 预览。

刷新网页不会创建新采集任务。网页重新读取本地状态后，可以继续显示并停止
已经运行的任务。

## 保存规则

保存根目录固定为：

```text
/Users/stephenapollo/Desktop/proj/edgeDeploy_GS/data
```

目录结构：

```text
data/
└── <数据集名称>/
    ├── 00001_20260731T120000_123.jpg
    ├── 00002_20260731T120000_623.jpg
    └── metadata.csv
```

数据集名称在去除首尾空白后长度必须为 1–64 个字符。允许中文、英文字母、
数字、空格、下划线和连字符；拒绝 `/`、反斜杠、控制字符、`.`、`..`
以及任何解析后越过 `data` 根目录的路径。

同名数据集再次采集时，扫描现有 JPEG 的数字前缀并从下一个编号继续，不覆盖
旧文件。文件名包含五位递增编号和本地时间。

图片先写入同目录的 `.part` 临时文件，写入和刷新成功后使用原子重命名生成
`.jpg`。失败的临时文件会被清理，不计入成功数量。

`metadata.csv` 每张成功图片追加一行，字段包括：

- 相对文件名；
- 数据集名称；
- 递增编号；
- 带时区的采集时间；
- JPEG 字节数；
- SHA-256；
- ESP32 来源 URL。

## 采集节奏与并发

- 默认拍照间隔为 500 ms，可在网页调整。
- 合法范围为 200–60,000 ms。
- 间隔从一次成功保存完成后开始计算。
- 同一时间只允许一个后台采集任务。
- 对 ESP32 的请求严格串行，不发送重叠 `/capture` 请求。
- 本地服务使用停止事件协调线程，不强制终止正在写文件的操作。

## 错误处理

- 单张获取失败后最多额外重试 2 次。
- 重试之间等待 500 ms。
- 一张图片在全部重试失败后计为一次失败，然后继续下一张。
- 连续 5 张图片失败时自动停止整个任务。
- 无效 Content-Type、非完整 JPEG、非 128×128 响应或写盘失败均视为失败。
- 数据集名称非法、间隔越界或已有任务运行时，开始接口直接拒绝且不创建目录。
- `data` 目录创建失败时不启动采集。
- 关闭 Python 程序时设置停止事件并等待采集线程退出。

页面显示最近一次错误。已经原子保存成功的图片不会因为之后的错误或停止操作
而丢失。

## HTTP 控制接口

本地服务提供最小接口：

- `GET /`：控制网页；
- `GET /api/status`：当前任务、计数、最新文件和错误；
- `POST /api/capture/start`：提交数据集名称和间隔并开始；
- `POST /api/capture/stop`：停止当前任务并返回最终状态。

接口只接收和返回 JSON。服务默认绑定回环地址，不接受局域网其他设备访问。

## 测试设计

主机自动化测试覆盖：

- 合法和非法数据集名称；
- 保存路径不能越过 `data` 根目录；
- 同名目录连续编号且不覆盖；
- JPEG Content-Type、头尾和 128×128 响应校验；
- `.part` 写入和原子重命名；
- `metadata.csv` 逐张追加；
- 单任务互斥；
- 默认间隔和间隔边界；
- 开始、停止和刷新后状态恢复；
- 单张重试和连续 5 次失败自动停止；
- 使用假 ESP32 HTTP 服务完成本地接口集成测试。

真机验收流程：

1. 连接 ESP32 SoftAP 并启动本地采集服务。
2. 新建测试数据集，使用 500 ms 间隔采集 10 张。
3. 点击停止，确认 MJPEG 预览恢复。
4. 核对目录中有 10 张不重名 JPEG 和 10 行元数据。
5. 核对每张图片为 128×128 且 JPEG 完整。
6. 核对 ESP32 状态中没有新增采集失败或流失败。
